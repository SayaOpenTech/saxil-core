# نتیجهٔ آزمون تازهٔ runtime مرجع

تاریخ: ۲۹ اکتبر ۲۰۲۶ — مدل qwen/qwen3.5-9b، ارائه‌دهندهٔ ثابت Parasail، از طریق OpenRouter.

## نتیجهٔ قابل اتکا

آزمون ۱۲۰ نمونهٔ ساختگی در ۱۲ خانواده با سه seed استنتاج و سه شیوهٔ خروجی اجرا شد: ۱۰۸۰ درخواست. در تمام پاسخ‌هایی که سرویس برگرداند، عمل، نقش‌ها، نام و مقدار دقیق صحیح بودند. هیچ خطای معنایی یا خراب‌شدن رقم و نام مشاهده نشد. هر هشت شکست، HTTP 429 بود.

| روش | پاسخ صحیح / همهٔ درخواست‌ها | پاسخ صحیح / پاسخ‌های دریافتی | خطای ارتباطی |
|---|---:|---:|---:|
| JSON با تولید مستقیم متن دقیق | ۳۵۵/۳۶۰ | ۳۵۵/۳۵۵ | ۵ |
| JSON با مرجع و resolver | ۳۵۹/۳۶۰ | ۳۵۹/۳۵۹ | ۱ |
| خروجی کوتاه alias با همان resolver | ۳۵۸/۳۶۰ | ۳۵۸/۳۵۸ | ۲ |

بنابراین اختلاف نرخ موفقیت کل را نمی‌توان به بهترشدن دقت مدل نسبت داد. مقایسهٔ جفت‌شدهٔ JSON مرجع با تولید مستقیم، اختلاف ۱٫۱۱ واحد درصد داشت؛ بازهٔ اکتشافی bootstrap با خوشه‌بندی بر اساس ۱۲۰ نمونه، از صفر تا ۲٫۵ واحد درصد بود. اختلاف alias با JSON مرجع منفی ۰٫۲۸ واحد درصد و بازهٔ آن منفی ۱٫۳۹ تا مثبت ۰٫۵۶ واحد درصد بود. سه seed تکرار استنتاج روی همان نمونه‌ها هستند؛ سه آموزش مستقل نیستند.

## مصرف توکن

میانگین توکن در پاسخ‌های موفق:

| روش | ورودی | خروجی | مجموع |
|---|---:|---:|---:|
| تولید مستقیم JSON | ۳۳۱٫۵۰ | ۶۸٫۵۱ | ۴۰۰٫۰۱ |
| JSON مرجع | ۲۷۲٫۶۷ | ۵۵٫۹۲ | ۳۲۸٫۵۹ |
| alias کوتاه | ۲۷۴٫۷۱ | ۹٫۳۵ | ۲۸۴٫۰۶ |

در این مجموعه، alias نسبت به JSON مرجع حدود ۸۳٫۳٪ توکن خروجی کمتر و حدود ۱۳٫۵٪ توکن مجموع کمتر مصرف کرد. این یک توصیف از خروجی کوتاه در همین آزمون است؛ از آن مزیت اختصاصی SAXIL، صرفه‌جویی همگانی توکن، یا عملکرد توکنایزر بومی R2 نتیجه نمی‌گیریم. JSON نیز می‌تواند قرارداد خروجی کوتاه یا فشرده داشته باشد.

زمان میانهٔ دیواری API به‌ترتیب حدود ۱۹۷۷، ۱۸۴۴ و ۱۳۷۵ میلی‌ثانیه بود؛ درخواست‌ها با هم‌زمانی شش اجرا شدند و این زمان، تأخیر کل شبکه و سرویس را شامل می‌شود. این اندازه‌گیری شاهد علّی سرعت مدل، کدک یا دستیار صوتی نیست. هزینهٔ گزارش‌شدهٔ خود ۱۰۸۰ درخواست حدود ۰٫۰۴۳۳ دلار بود؛ بررسی‌های اولیهٔ سرویس جدا هستند.

## اعتبار آزمون و حدود آن

- جدول‌ها پیش از ساخت پاسخ مطلوب از دادهٔ ساختگی ساخته شدند؛ همهٔ مرجع‌های هدف منبع ورودی مشخص دارند. هیچ دادهٔ تاریخی، نام خصوصی یا وزن مدلی به API ارسال نشد.
- داده، پرامپت، کد اجرا و runtime پیش از استنتاج هش‌گذاری شدند. امتیازدهی مستقل از محتوای خام پاسخ‌ها، صفر اختلاف با امتیازدهی اولیه داشت و seal معتبر ماند.
- DeepInfra در بررسی اولیه با engine_overloaded پاسخ داد؛ هیچ نمونهٔ آزمون به آن ارسال نشد. نسخهٔ دوم با همان داده و ارائه‌دهندهٔ Parasail اجرا شد. ارائه‌دهنده در میانهٔ آزمون عوض نشد و درخواست‌های ناموفق تکرار نشدند.
- در این آزمون، درخواست معنایی از قبل برای میزبان مشخص است. این آزمون فهم متن آزاد فارسی را نمی‌سنجد و یک realizer قطعی نیز برای بازسازی همین فیلدهای مشخص کافی است.
- aliasهای این آزمون یک قرارداد سادهٔ انتخاب برای runtime آزمایشی هستند؛ W2 یا نمایش native مدل پژوهشی نیستند.

## تصمیم انتشار

کد تازه، دادهٔ ساختگی، پروتکل و نتیجهٔ مثبت و منفی برای بازبینی پژوهشی آماده‌اند. معیارهای ساختاری runtime روی wheel نصب‌شده با ۱۹ آزمون پاس شدند. بسته هنوز یک نامزد محلی و آزمایشی است.

بازتولید مدل 4B پژوهشی همچنان انجام نشده است. راه‌اندازی مجدد Runner موفق بود، اما آزمون بدون ابزار RUN-20261029-0005 هم پیش از پاسخ عامل با startup_timeout متوقف شد. کنترل integrity برای فایل باینری SAXIL از ابزار موجود نیز قابل استفاده نشد. تغییر تنظیمات امنیتی یا جایگزین‌کردن این آزمون hosted به‌جای بازتولید اصلی انجام نشد.

بررسی دقیق‌تر کد آزمایش entity نشان داد بازوی literal، مدل فریزشدهٔ SV3 را بارگذاری کرده و بازوی sidecar از SV3R آموزش‌دیده استفاده کرده است. پس بهبود تاریخی ۴۹٫۰۴٪ به ۸۳٫۶۵٪، مقایسهٔ صرفاً تعویض قالب روی یک checkpoint یکسان نیست. بازتولید باید این تفاوت را حفظ کند؛ برای نسبت‌دادن اثر به نمایش به‌تنهایی، کنترل فرصت آموزش نیز لازم است.

انتشار نسخهٔ پایدار یا بستهٔ کامل‌تر شامل مدل، هنوز نیازمند بازاجرای اصلی و تعیین هویت و منشأ دارایی‌های مدل است. نتیجهٔ فعلی مجوز ادعای برتری دقت SAXIL بر JSON یا عرضهٔ قابلیت‌های مدل بومی در SDK عمومی را نمی‌دهد.
